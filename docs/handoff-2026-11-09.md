### 2.1 知识层

- 学科（Discipline）：21 个，例如数学、物理、计算机、AI、医学、工学、艺术。
- 知识点（KnowledgePoint）：116 个，带 `code`、`level`（1–4）、`discipline_code`。
- 先修边（KnowledgePointEdge）：120 条，`from -> to` 表示先学 from 才能学 to。
- 资源关联（ResourceKnowledgePoint）：按标题/标签/描述关键词匹配，`MatchScore >= 0.5` 才关联。
- 概念层（KnowledgeConcept）：来自 MOOCCube 的概念图，425 个概念 / 1027 条先修边；概念图可能有环，学科层用严格拓扑，概念层用 SCC 容错的 `ComputeLevelsTolerant`。
- 实时生成概念：平台不跑 Python，只通过 HTTP 调 engine 的 `/knowledge/generate`；生成结果以 `source=generated` 落库，`code=GEN_<sha1前12>_<point>`。

### 2.2 学习路径

- 问卷：0–3 自评 → mastery 0 / 0.33 / 0.67 / 1。
- 行为：浏览等行为每次 +0.1，单知识点上限 0.6。
- 路径：按先修闭包 + 拓扑排序；mastery ≥ 0.8 视为已掌握并跳过；第一个未掌握为 `current`，其余 `locked`；完成当前才解锁下一个。
- 接口：
  - `GET /api/v1/learning-profile`
  - `POST /api/v1/learning-profile/questionnaire`
  - `POST /api/v1/learning-paths`
  - `GET /api/v1/learning-paths/:id`
  - `POST /api/v1/learning-paths/:id/complete`
  - `GET /api/v1/learning-paths/:id/resources`

### 2.3 关键帧/封面

- 爬虫：`backend/crawler/frames.py` 调 B 站公开接口：

### 3.4 学科页点击知识点/其他页面不能跳转（已修复）

根因：**接口序列化**，不是路由或遮罩。

- `GET /api/v1/disciplines/:code` 的 `resources` 直接返回 GORM `model.Resource`，JSON 字段是大写 `ID`、`CreatedAt` 等。
- 前端 `ResourceCard` 用 `resource.id` 生成 `RouterLink`，拿到 `undefined`。
- vue-router 抛 `Missing required param "id"`，随后卸载组件报 `Cannot read properties of null (reading 'type')`，整棵路由组件渲染中断。
- 表现：URL 变成 `/knowledge/calculus`，页面仍停在学科页；从该页去其他路由也一起失效。

修复：

- `backend/internal/handler/discipline.go`：学科详情的资源改用 `resourceListItem` DTO，和知识点详情一致。
- `backend/internal/handler/knowledge_http_test.go`：新增 `TestDisciplineDetailResourcesUseListDTO`，断言不能出现大写 `ID`，且 `id=63`。
- 返回字段现在包含：`id`、`title`、`description`、`cover_url`、`type`、`category`、`tags`（数组）、`author`、`avg_rating`、`view_count`、`difficulty`、`duration_minutes`、`created_at`。

验证：

- 后端全量 `go vet ./...`、`go test ./...` 通过。
- 浏览器实测（Edge CDP，1440×1200）真实鼠标点击「高等数学」：URL 到 `/knowledge/calculus`，H1 为「高等数学」，无异常。
- 800×600 无头窗口点击失败是因为卡片中心 y=567、视口高 487，链接在首屏下方；先滚动或放大视口即可，不是 bug。

### 本机环境坑（下次接手先看）

1. **`GOCACHE` 必须指到仓库内**：`$env:GOCACHE='E:\work\learn\edurec\.runtime\gocache'`，否则默认 `%LOCALAPPDATA%\go-build` 在受限沙箱里报 `Access is denied`。
2. **两个仓库目录里新建文件会被拒**：`edurec-platform` / `edurec-engine` 是从别处移动过来的，DACL 没继承新根目录的写入授权，`git add` 建不了 `.git/index.lock`、脚本写不进文件。写操作需要完全权限；读不受影响。
3. **msys 程序在受限环境起不来**：`bash`、`redis-cli` 报 `couldn't create signal pipe`（命名管道被禁）。用 `C:\Program Files\Git\bin\bash.exe` 并走完全权限；Redis 连通性可用 .NET `TcpClient` 直发 RESP 验证。
4. **`go run` 的进程树要一起杀**：只 kill 外层 `go run`，它派生的 `server` 子进程仍占着 8080，新实例起不来 → 表现为「改了代码没生效」。确认方式：看监听进程的启动时间。
5. **启动后端必须带** `CONFIG_PATH=configs/config.local.yaml`（3308/6380）；仓库默认的 `configs/config.yaml` 是 3306/6379。`backend/cmd/server/main.go` 里曾把默认值临时改成本地配置，已还原。
